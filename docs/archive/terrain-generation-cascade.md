# Terrain Generation — The Layered Candidate Cascade

**Status:** Draft architecture. The organizing model for all procedural body
generation in Thalos. Companions:

- [planet-generation-pipeline-spec.md](planet-generation-pipeline-spec.md) — the
  **field-DAG substrate** (fields, expr, stamps, generators, author overlay,
  quadtree cache, tile/output contract, caching tiers) this cascade is built on.
  That doc owns the low-level intent-layer mechanics.
- [planet-generation-pipeline-migration.md](planet-generation-pipeline-migration.md)
  — the **brownfield sequencing** that gets us here without a flag day. This
  cascade is the destination its P1/P2/P3 phases were heading toward.

This doc owns the *semantic* model: the cascade of layers, archetypes as type
registries, and the candidate tree.

## 1. The model

A body is generated by a **cascade of semantic layers**. Authored physical
parameters are the fixed input; each layer consumes the layers above it plus its
own **seed** and **author overlay**, and produces outputs the next layer reads.
Reroll a layer's seed and everything downstream regenerates; tweak a layer
(paint a field, place/move a feature) and the tweak persists across rerolls of
that layer. The whole cascade runs **essentially real-time in the editor**.

Two structures sit around the cascade:

- An **archetype** declares *what kinds of things can exist* on a body class —
  the catalog of biome types, terrain-generator types, and scatter types the
  cascade may instantiate.
- A **candidate** is a saved, labeled, branchable configuration of the whole
  cascade (every layer's seed + overlay). Candidates form a tree you author by
  branching; the **active** candidate (set explicitly) is what the game bakes
  and loads.

So: **archetype = the type system; the cascade + seeds = what specifically
exists where; candidate = a saved, version-controlled instance of that.**

## 2. Physical parameters (authored, fixed)

Not rerolled — the constraints the generators must satisfy: radius, mass /
gravity, bulk composition, age, insolation (semi-major axis + star luminosity),
rotation period, axial tilt, volatile inventory (water / ice / atmosphere
budget). They select (or the author picks) an archetype and condition every
layer.

## 3. The cascade

Each layer is deterministic: `(upstream outputs + physical params + seed +
overlay) → output fields`. Top to bottom; reroll cascades downward.

1. **Tectonics** — plates, boundaries, hotspots → structural intent (orogeny
   belts, rift zones, boundary distance). *The primary reroll.* (Exists:
   `crates/terrain/src/tectonics/`.)
2. **Macro topography** — from tectonics + physical params → continent/ocean
   distribution, macro elevation, sea level (from volatile inventory +
   hypsometry). Outputs `continent_sdf`, `elevation_intent`, `structural_intent`.
3. **Macro-climate** — from axial tilt + insolation + rotation + land/ocean +
   elevation → `temperature`, `humidity`, circulation. Independent of
   micro-relief, so it can drive what's below rather than be read back from it.
4. **Biomes** — classified from climate + elevation + tectonic province →
   `biome` (categorical, blended at boundaries). Each instantiated biome is a
   *type drawn from the archetype* and carries its three facets (terrain recipe,
   material palette, scatter set).
5. **Terrain generation** — per-biome height recipe conditioned on biome + macro
   topo + structural intent → the band-limited heightfield (the single
   mesh + collider surface).
6. **Large features** — placed by biome + tectonics (volcanoes at hotspots /
   convergent margins, impact craters, canyons, basins).
   `TerrainModification` → composited into the heightfield; `SurfaceInstance` →
   scatter. (Catalog exists: `pipeline::feature`.)
7. **Materials** — form-selection within each biome's palette + universal
   cross-cutting materials (rock / snow / sand / ice / seabed) →
   albedo / roughness / material-splat + shading model. (The P2C materials-first
   work folds in here.)
8. **Scatter** — each biome's scatter set (trees / grass / pebbles / boulders),
   density-modulated by form and material. (Catalog exists.)

Snow and rock are **materials, not biomes** — selected by form across all biomes
(the materials-first inversion from §P2C of the migration doc).

### Scatter & vegetation — the LOD continuum (layer 8)

Trees, grass, boulders, and structures are **`SurfaceInstance`** content — they
rest *on* the surface, distinct from `TerrainModification` features (craters,
mesas) that *are* the heightfield. Size doesn't decide it; the test is "does it
change the ground shape (terrain) or sit on it (scatter)?" A giant tree is
scatter; a small mesa is terrain.

Scatter renders as **one definition expressed across a continuum of
representations that agree in aggregate**, so it resolves in smoothly instead of
popping — the same far↔near invariant as terrain (§P2C). Far → near:

1. **Far = a material (layer 7).** A forest from orbit is not instances — it is
   the terrain's *shading*. "Forest canopy" and "grass field" are **shading
   models** (translucent / subsurface scattering, fuzzy soft specular, canopy
   AO), modulated by the scatter density field. The "fluffy field scattering
   light" *is* a BRDF. This is a primary reason the materials layer needs
   arbitrary shading models — grass-field and canopy are two of them — and it
   means the far LOD of vegetation is produced **for free** by the impostor +
   ground-tile material path.
2. **Mid = impostors / shells.** Octahedral / billboard tree clusters;
   shell-and-fin or carded grass. Density-faded.
3. **Near = instances.** GPU-compute-instanced grass blades and tree meshes
   (with their own mesh LODs), faded in by smoothly lowering the cull threshold
   on the same UDLOD tile-distance keying as terrain.

Because tier 1 already nails the aggregate look, nearer tiers only *add*
resolvable geometry — nothing pops. The far aggregate (a layer-7 material) and
the near instances (layer 8) are the **same biome scatter definition** at two
LODs, which is what guarantees they agree.

Collision follows the split: grass has none; trees get **windowed per-instance
colliders** attached only near a physics body (the fernweh windowed-
reconciliation pattern, migration §6), so cost is bounded by what's near the
player, not planet size. Dense scatter (grass, pebbles) is GPU-instanced and is
never ECS entities; sparse collidable scatter (trees, boulders, structures) is
ECS with windowed spawn / despawn.

## 4. Archetypes — type registries

An archetype is a body-class definition that declares the **catalog of
layer-resident types** available, plus archetype-level conditioning:

- **biome types** — e.g. oceanic-terrestrial: {ocean, shelf, beach, forest,
  grassland, steppe, boreal, tundra, alpine}; airless-impact: {highland
  regolith, mare basalt, fresh ejecta}.
- **primary generator types** — the terrain recipes available (continental,
  orogenic ridges, dune sea, crater plains, …).
- **scatter types** — trees/grass/pebbles/boulders vs. just boulders, etc.
- **conditioning** — tectonic mode, climate-model variant, default sea-level
  behaviour.

The cascade *selects and instantiates* from the archetype's catalog per region:
climate picks which biome type; the biome picks its generator and scatter set.
Adding a body class = declaring an archetype + its type sets; adding a
biome / generator / scatter type = a catalog entry, no engine change. This
generalizes today's hardcoded `BodyArchetype` enum into a data-driven registry.

## 5. Reroll, cascade, tweak — real-time

- **Seed per layer.** Reroll(layer) = new seed → recompute that layer + all
  downstream. Reroll tectonics = new world; reroll biomes = biomes / terrain /
  materials / scatter change while everything upstream holds. Reuses the
  5-stream `FeatureSeed` + `FeatureLock` reroll-with-lock that already exists.
- **Overlay per layer.** Tweaks are a replayable op-log composed onto the
  procedural value via two-path composition — reroll never disturbs the overlay,
  painting never disturbs the procedural value. Reuses `pipeline::AuthorOverlay`.
- **Cascade invalidation.** A change marks only downstream layers dirty in the
  affected region; the quadtree cache + intent-cache reuse keep recompute
  **near-real-time**. Only the touched region and what depends on it recomputes.

## 6. Candidates — the authoring version tree

A **candidate** captures the entire cascade configuration: per-layer
(seed + overlay), the archetype, and the physical params. Candidates form a
**tree**:

- **branch** from any candidate (fork to explore a variation),
- **label** candidates ("wetter continents", "high-tilt ice world"),
- **reroll / tweak** within a candidate edits its config,
- **active** candidate (set explicitly) = the one the game bakes and loads.

Tweak-persistence across reroll falls out of the tree: a layer's overlay lives
inside its candidate. Rerolling an upstream layer orphans downstream overlays
*on that experimental branch*, but they remain intact in the candidate they were
authored in — **branch first, reroll on the branch, and the original candidate
(with its tweaks) is still there to make active again.** "Roll back the stable
seed" = make a prior candidate active.

Storage: the candidate tree is per-body authored data (RON) with an `active`
pointer. The game reads only the active candidate; the editor manipulates the
whole tree.

## 7. What we reuse — "it distills to this"

The cascade is the **distillation** of the existing field-DAG: each semantic
layer is a named group of fields produced by a seeded generator with an overlay,
and the cascade is the DAG's topological order made semantic and coarse-grained.
Concretely reused:

- field-DAG (`pipeline::{field, expr, dag, stamp, planet, storage}`) — the field
  substrate, automatic ordering, two-path composition, quadtree cache.
- seed system (`sub_seed` / `splitmix64` / `FeatureSeed` / `FeatureLock`) —
  per-layer reroll-with-lock.
- tectonics (`tectonics/`) — layer 1, essentially as-is.
- feature catalog (`pipeline::feature`) — layers 6 and 8.

Net-new: the **semantic layer structure** (named cascade vs. flat field bag), the
**archetype type-registry**, the **candidate tree + active pointer**, and
**de-fusing** the monolithic `sample_oceanic_continental` into layers 2–7.

## 8. Build sequence (strangler-fig, top-down)

The live pipeline keeps working until each layer replaces its fused part.

1. **Framework spine** — the `Layer` contract (inputs / seed / overlay / output),
   the cascade graph with dirty-tracking + recompute, and the **candidate tree**
   (branch / label / active, RON persistence) — on the existing field-DAG + seed
   primitives.
2. **Tectonics layer** wired end-to-end, rerollable in the editor — proves
   cascade + reroll + overlay + candidate + real-time on the layer that already
   exists.
3. **Macro-topo → climate → biomes → terrain**, de-fusing
   `sample_oceanic_continental` one layer at a time.
4. **Features, materials (P2C), scatter** onto their catalog primitives.
5. **Archetype registry** generalizing `BodyArchetype`, then port each body.
